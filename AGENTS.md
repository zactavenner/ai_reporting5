- Quality Feedback (Meta quality signals) lives in `supabase/functions/_shared/qualityFeedback/` (pure core + DB store), `quality-feedback-api` (operator-only) and `quality-feedback-worker` (trigger-fed queue + hourly reconciliation + gated outbox). Why: keeps evaluation off the lead-intake path and every send behind global gate + per-client activation.
- Facebook Instant Form lead backfills to a client's KPI sheet go through `meta-form-leads-to-sheet` (operator or internal-secret only, dry-run by default, dedupes on email/phone). Why: fills sheet gaps when CRM delivery breaks without exposing contact details in responses.
- External assistants (Grok PPM, Alfred, Muse, Claude) live in `external_agents` (service-only) with logic in `supabase/functions/_shared/externalAgents/` (pure `core.ts` + `dispatch.ts`), `external-agents-api` (operator-only), `external-agent-worker` (wake-on-enqueue + hourly sweep) and `external-agent-callback` (per-agent HMAC + nonce; also the outbound-only Mac worker poll/claim/session endpoint used by `tools/mac-agent-worker/worker.mjs`). Why: task assignment wakes real agents only through a durable, idempotent outbox, never by model personas or unverified connections.
- Content → Video Ads pipeline lives in `src/components/content-ads/` (VideoPipeline + TemplateLibrary) and reuses the shared `masterVideoContract` (720p default, script-derived duration via `suggestDurationForScript`, `costEstimate`) plus the exact-model path of `generate-video-from-image`; reference vs template libraries are the `library` column on `ai_studio_reference_videos/images`. Why: one contract keeps UI estimates and server-side spend rules identical, and agents read the same library tables humans do.
- Setter call scripts live in `setter_scripts` (client_id null = agency default; pure picking/matching in `src/lib/setterCoach.ts`). Why: one playbook shared by human setters and later the AI caller.
- Setter browser calls go through `setter-twilio-call` (Twilio gateway, ring setter then <Dial> lead) with live transcripts posted to `setter-call-events` using a per-call token hidden from the browser. Why: the gateway hides Twilio secrets, so Voice SDK access tokens can't be minted.
- Client reporting (Analytics → Reporting, any date range) reuses `supabase/functions/_shared/weeklyReport/` (`buildRangeReport`, `dailyRows`, `reportFacts`); review notes live in service-only `client_report_reviews`, written by `client-report-review` (operator: AI review/notes; linked agents: read facts) and agent RPC `mcp_agent_post_report_review` via MCP tools `get_client_report`/`post_report_review`. Why: screen, PDF, AI and agents all read one set of verified numbers, and reviews never edit source data.
- AI Influencer Studio (Content → AI Influencers) lives in `src/components/influencer-studio/` with the pure contract in `supabase/functions/_shared/influencerStudio/core.ts` (re-exported by `src/lib/influencerStudio.ts`) and all reads/writes through `influencer-studio` (service-only `influencer_projects`; characters are client-scoped `avatars` rows with `metadata.kind='influencer'` plus `avatar_looks`). Why: UI readiness and the server render gate share one module, motion swap only runs on models that honour video `input_references`, and paid renders stay on the active price allowlist.
- Per-client Meta system user tokens live encrypted in service-only `client_meta_system_tokens`; every Meta pull gets its token from `resolveClientMetaToken` (`supabase/functions/_shared/metaSystemToken.ts`), which falls back to the function's previous token choice unchanged. Why: one reader keeps the token server-side, logs which token each pull used, and retries once on the user token if Meta rejects the system token.
